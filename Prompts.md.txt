# Sprint 12 — AI Prompt Engineering Documentation

**Project:** Storybook Component Library  
**Track:** Track A — Frontend Specialist  
**Phase:** Phase 4 — Advanced Integration  
**Sprint:** Sprint 12 — Real-Time Systems & UI Isolation

---

## 1. Project Objective

The objective of this sprint is to configure Storybook within an existing Next.js/React project and develop an isolated, reusable UI component library.

The implementation focuses on three core components:

1. Button
2. Input Field
3. Card / Product Card

The component library must support interactive Storybook Args and Controls, component variants, Light Mode and Dark Mode, and static Storybook deployment.

AI assistance is used to support implementation, configuration, debugging, and documentation. Generated code must be reviewed and tested against the actual project.

## 2. Prompt Engineering Strategy

The development workflow follows these principles:

- **Inspect before modifying:** Understand the existing repository, framework, file structure, dependencies, and styling system before making changes.
- **Implement incrementally:** Complete and verify Phase 1 before starting Phase 2, then complete Phase 3.
- **Preserve existing code:** Avoid unnecessary changes to the main Next.js/React application.
- **Debug using evidence:** Use actual terminal errors and build output rather than guessing.
- **Verify before declaring completion:** Mark requirements complete only after checking the actual implementation.
- **Document accurately:** Record the commands, changes, and verification results that actually occurred.

# PHASE 2 — Variant Engineering & Theming (P1)

**Objective:** Make components interactive through Storybook Controls.

**Prompt:**

Implement interactive Args and Controls for the Button, Input Field, and Card stories.

### Button

Provide controls for:

- Variant: Primary and Secondary
- Disabled: true and false
- Size: Small, Medium, and Large

### Input Field

Provide suitable controls for:

- Label
- Placeholder
- Disabled state
- Value or other appropriate input properties

### Card / Product Card

Provide suitable controls for:

- Title
- Description
- Content or image, where appropriate
- Other useful presentation properties

Implementation requirements:

1. Use the installed Storybook version's supported Args and Controls APIs.
2. Define sensible default values.
3. Ensure controls update the component preview.
4. Avoid duplicating complete components for individual variants.
5. Keep types, property definitions, and story metadata consistent.
6. Preserve the existing application and styling system.

**Verification:**

Open each story, change its controls, and confirm that the preview responds to the selected values.

**Objective:** Support theme switching in Storybook.

**Prompt:**

Implement Light Mode and Dark Mode support for my Storybook component library.

Requirements:

1. Provide a convenient way to switch between Light Mode and Dark Mode in the Storybook environment.
2. Ensure Button, Input, and Card render appropriately in both themes.
3. Reuse the existing theme system if the project already has one.
4. Configure global styles, CSS variables, or Tailwind classes as appropriate to the actual project.
5. Ensure component text, backgrounds, borders, and focus states remain readable.
6. Avoid duplicating the entire main application.
7. Use an approach compatible with the installed Storybook version.

After implementation, explain how to switch themes and test every component in both modes.

Do not claim theme support is complete without checking the actual previews.

**Verification:**

Switch between themes and inspect the Button, Input, and Card stories in both Light Mode and Dark Mode.
